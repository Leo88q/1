# Интеграция «Амперграда» в GUTTERCAPS

Здесь лежит то, что уходит в `github.com/Leo88q/guttercaps` **отдельным механизмом**:
экран-головоломка внутри их клиента, на их палитре и их арт-правилах, без общего с
ними хозяйства (никаких мостов ассетов, общей казны и общего токена).

| Путь | Что это |
|---|---|
| `pr/docs/12-ampergrad-mechanism.md` | описание контура для их `docs/`: правила, арт-контракт, награды, события, выкатка, не-цели |
| `pr/packages/ampergrad/` | пакет для их монорепо: правила на чистом TS, 12 кварталов канона, 10 тестов, образцы арта и манифест |
| `tools/prepare-samples.py` | собирает `pr/.../art/` из арта репозитория (уменьшенные образцы, pillow) |
| `tools/pr-body.md` | описание PR |
| `tools/open-pr.sh` | открывает или обновляет PR в `Leo88q/guttercaps` через API |
| `patch/ampergrad-mechanism.patch` | тот же коммит патчем: ложится на их `main` через `git am` |
| `tools/build-patch.sh` | пересобирает патч из `pr/` (и сразу сверяет результат) |
| `tools/check-patch.mjs` | сверка патча с пакетом по sha-блобам; гоняется в CI |
| `tools/land-pr-locally.sh` | укладывает патч в ваш клон GUTTERCAPS и открывает PR |

## Почему через Git Data API, а не клоном

Их репозиторий — около 1.2 ГБ, и клонировать его ради документа и пакета незачем.
`tools/open-pr.sh` собирает один коммит поверх их `main` из блобов и обновляет ветку
`arena/77b06826-ampergrad`. Скрипт безопасен для повторного запуска: он **не** трогает
их `main`, только свою ветку.

## Доставка PR

Токен сессии Arena выдан только на репозиторий «Амперграда», поэтому писать в
`Leo88q/guttercaps` из сессии нельзя (API отвечает `403 Resource not accessible by
integration`). Два равнозначных пути:

1. **Со своей машины (работает сразу).** Патч `patch/ampergrad-mechanism.patch` уже
   собран и проверен: он ложится на их `main` через `git am`, конфликтов не даёт
   (все файлы новые).

   ```bash
   bash integrations/guttercaps/tools/land-pr-locally.sh ~/Desktop/guttercaps
   ```

2. **Из сессии (если откроете доступ).** Подключите GitHub заново в Arena и дайте
   доступ к `guttercaps` — тогда тот же коммит уедет через API:

   ```bash
   bash integrations/guttercaps/tools/open-pr.sh
   ```

Оба пути создают **одну и ту же** ветку `arena/77b06826-ampergrad` и один и тот же
коммит: содержимое берётся из `pr/`, ничего не генерируется заново.

## Как пересобрать и отправить

```bash
python3 integrations/guttercaps/tools/prepare-samples.py   # образцы арта (нужен pillow)
node --experimental-strip-types --test integrations/guttercaps/pr/packages/ampergrad/test/*.test.ts
bash integrations/guttercaps/tools/build-patch.sh          # пересобрать патч после правок в pr/
node integrations/guttercaps/tools/check-patch.mjs         # сверка патча с пакетом (то же делает CI)
bash integrations/guttercaps/tools/open-pr.sh              # PR в Leo88q/guttercaps (если есть права)
```

Правка в `pr/` **требует** пересборки патча: `npm run` его не собирает, а CI сверяет
патч с пакетом по sha-блобам и падает, если они разъехались. Так устаревший код не
уедет в чужой репозиторий.

## Что проверяемо локально

Тесты механизма гоняются встроенным раннером Node (22+) на 12 кварталах канона:
решение собирает квартал, стартовая раскладка не собрана, `parMoves` совпадает с
контентом, кресты не вращаются, подсказки доводят до победы.

## Экономика

Не пересекается. В их `docs/INTERWEAVING.md` прямо сказано, что кросс-игрового моста
нет и идентичность — это pubkey кошелька; мы это уважаем: играем без кошелька, пломбы
(cNFT) минтятся в нашей программе, локальные монеты скинов не обмениваются ни на $CG,
ни на SOL. Награды — предмет без ценности вне игры; никаких взносов и выплат «за вход».
