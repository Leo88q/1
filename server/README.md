# Сервер Амперграда (клейм наград и челлендж дня)

Сервер делает две вещи:

1. **Выдаёт награды (cNFT)** — по подписи кошелька и доказательству решения.
2. **Проверяет результаты челленджа дня** — общий уровень для всех игроков.

Ключевой принцип: **игрок ничего не платит**. Кошелёк подписывает только сообщение
(proof of ownership), транзакцию минта выполняет сервер своим ключом.

## Почему доказательство решения, а не «подпись результата»

Подпись кошелька доказывает владение кошельком, но не честность игры.
Поэтому клиент присылает `proof` — последовательность своих поворотов, а сервер
**проигрывает её тем же ядром правил** (`@ampergrad/engine`) и убеждается, что
квартал действительно собран. Так работает и клейм, и лидерборд дня.

Клиент и сервер обязаны использовать одну версию правил: `ENGINE_VERSION`.
Если ядро меняется, версия поднимается, а приложение с прежней версией
получает понятный отказ (409), а не молчаливую порчу результатов.

## Поток клейма

```
1. Приложение: POST /claim/start  { address, engine, proof? }
   Сервер: проверяет proof (если прислан), засчитывает прогресс,
           подбирает доступную награду, отдаёт { nonce, message, rewardId }
2. Кошелёк (MWA): подписывает message (signMessagesDetached)
3. Приложение: POST /claim/submit { address, nonce, signature, rewardId, proof }
   Сервер: nonce одноразовый + TTL, проверяет Ed25519-подпись,
           правила награды, лимиты → минт cNFT → { status, assetId, txSignature }
```

Статусы: `minted` (награда в сети), `queued` (режим dry-run: ничего не тратится),
`failed` (ошибка минта — награда не списывается, клейм можно повторить).

## Запуск

```bash
cd server
cp .env.example .env            # заполнить по необходимости
npm run dev                     # http://0.0.0.0:8787
```

Без `DATABASE_URL` работает хранилище в памяти (только разработка).
Для продакшена: Postgres + `psql "$DATABASE_URL" -f schema.sql`.

## Настройка сети

| Режим | Что нужно | Что происходит |
|---|---|---|
| `dry-run` (по умолчанию) | ничего | награда «в очереди», приложение показывает честный статус |
| `devnet` | RPC, ключ минта, Merkle-дерево | реальные минты в devnet — полная проверка потока |
| `mainnet` | то же + ~0.2 SOL и дерево | боевая выдача наград |

Создание Merkle-дерева Bubblegum:

```bash
AMPERGRAD_MINT_MODE=devnet AMPERGRAD_RPC_URL=... AMPERGRAD_PAYER_SECRET=... \
npm run tree -- --max-depth=14 --canopy=11
# → прописать полученный адрес в AMPERGRAD_MERKLE_TREE
```

На mainnet скрипт требует явного `--yes-mainnet`: покупка дерева — это реальные SOL.

## Сквозная проверка без сети

```bash
npm run simulate
```

Скрипт создаёт тестовый кошелёк, строит честное доказательство решения уровня 1,
проходит весь поток (`/claim/start` → подпись → `/claim/submit`) и печатает результат.

## Безопасность и анти-спам

- Приватный ключ минта — только в окружении/KMS, никогда в репозитории и в APK.
- `nonce` одноразовый, живёт `AMPERGRAD_CHALLENGE_TTL_MS` (по умолчанию 5 минут).
- Лимиты: `AMPERGRAD_MAX_CLAIMS` (всего на кошелёк) и `AMPERGRAD_MAX_CLAIMS_PER_DAY`.
- Одна награда каждого типа — один раз на кошелёк.
- `AMPERGRAD_ALLOW_UNVERIFIED=true` разрешает клейм без доказательства — только
  для отладки на devnet; в проде должно быть `false`.
